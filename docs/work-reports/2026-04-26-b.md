## Task 3: Bulk-Migrate the Remaining 23 Posts via Scraper Script
**Project:** Brio Website — Blog Content
**Date:** 2026-04-26
**Hours:** 1.75
**Category:** Feature

**Summary:**
Built `scripts/migrate-blog.mjs` — a Node.js migration tool that fetches each WordPress post directly from the live site, extracts the article body from Elementor's widget structure, converts HTML → Markdown, downloads the cover image, and writes a complete MDX file with frontmatter. Iterated through three extraction failures: (a) initial extractor matched the wrong DOM ancestor and pulled in the navbar; (b) second iteration's break condition fired prematurely because `node.contains(categoriesEl)` matched the body element; (c) third iteration used `og:title` for title detection but SEO-customized OG titles diverged from on-page H2s, missing matches. Final design uses the document-order-first `.elementor-heading-title` element as the article title anchor and walks the DOM via `TreeWalker` collecting only whitelisted widget types (text-editor, heading, image, icon-list, image-box) until reaching the "Categories" sidebar heading.

**Key Changes:**
- Installed `turndown` + `jsdom` for HTML → Markdown conversion
- `scripts/migrate-blog.mjs`: per-post metadata array (slug, ctaService, tags) drives the migration; everything else (title, date, category, cover URL, alt text, excerpt) auto-derived from OG meta tags
- Body extraction targets Elementor's `data-widget_type="text-editor.default"` widgets between the title heading and "Categories" heading
- Markdown cleanup pipeline strips body-level H1s (demoted to H2), `### by BRIO Team` bylines, date-only paragraphs, "Image Source:" orphan lines, base64 image placeholders, and converts `https://builtbybrio.com/` → relative paths
- All 23 posts migrated successfully (5 KB-41 KB body sizes, all generate cleanly via `generateStaticParams`)
- Cover images downloaded per slug to `public/images/blog/{slug}/cover.{webp,jpg,png,jpeg}`

## Task 4: Fix Blog Hero Image + Title Readability
**Project:** Brio Website — Blog Components
**Date:** 2026-04-26
**Hours:** 0.5
**Category:** Bug Fix

**Summary:**
Cover images were murky and titles unclear in the post hero. Two compounding causes: (a) the image had `opacity-70` AND a heavy navy gradient `from-brio-navy via-brio-navy/70 to-brio-navy/30` darkening the entire frame; (b) the H1's `text-white` utility class was being overridden to navy by the unlayered `h1, h2, h3, h4 { color: var(--color-text-dark) }` rule in `globals.css:30` — the same Tailwind v4 cascade-layer bug that hit the financing-page headline earlier. Fixed both: removed image opacity, replaced the full-frame gradient with a bottom-only `from-black/85 via-black/55 to-transparent` that only darkens behind the title block, added `!text-white` to override the unlayered rule, and added subtle `text-shadow` on title/dek/category as defense against bright cover photos.

**Key Changes:**
- Updated `components/blog/HeroCover.tsx`: removed `opacity-70` from the `<Image>`, swapped the full-frame navy gradient for a bottom-only black gradient
- Added `!text-white` (Tailwind important modifier) to the H1 to defeat the unlayered globals.css rule
- Added inline `style={{ textShadow: "0 2px 12px rgba(0,0,0,0.6)" }}` on the H1 (less aggressive shadows on category + dek)
- Simplified the blog index headline from a long sentence to a tight centered "Renovation guides & design ideas" + 2-line dek

## Task 5: Fix Frontmatter Rendering as Visible Body Content
**Project:** Brio Website — MDX Pipeline
**Date:** 2026-04-26
**Hours:** 0.5
**Category:** Bug Fix

**Summary:**
After the migration deployed, every post displayed its YAML frontmatter (title, slug, date, tags, coverImage URL, alt text, excerpt) as a giant bold/serif/underlined heading at the top of the body. Root cause: `@next/mdx` does not handle frontmatter natively — without `remark-frontmatter`, the leading `---` is parsed as a thematic break, the YAML key:value lines collapse into a single paragraph, and the closing `---` gets interpreted as a setext H2 underline. The result: the entire frontmatter block becomes one fake H2 heading, then `rehype-autolink-headings` (configured with `behavior: "wrap"`) wraps it in `<a>` tags, producing the bold-underlined-serif appearance the user reported. Fixed by installing `remark-frontmatter` and adding it to the remark plugins array in `next.config.ts` (before `remark-gfm`). The plugin recognizes `---...---` blocks as YAML metadata and excludes them from the rendered output. `gray-matter` continues to read the frontmatter independently for `lib/blog.ts` data needs.

**Key Changes:**
- Installed `remark-frontmatter`
- Updated `next.config.ts` `remarkPlugins` array to `["remark-frontmatter", "remark-gfm"]`
- Build passes, posts now render hero (cover image + title from frontmatter) at the top followed by clean body starting with the actual H2

**Commits:** `60cec8f`
